Working name: MarginRoute. We study when an already deployed document retriever should pay for a slower cross-encoder reranker. The contribution being investigated is a simple routing rule with no additional trainable router, not a new retriever or reranker. Existing alternatives in this study are rerank every query, never rerank, random routing, and a query-length rule. No exhaustive novelty search has occurred.
For query q, a frozen dense retriever returns k=20 documents d_1,...,d_20 with scores s_1 >= ... >= s_20. Compute g(q)=s_1-s_2. If g(q)<tau, run the fixed cross-encoder on all 20 retrieved documents and return the document with the largest cross-encoder score. Otherwise return d_1. No labels are used at test time. The retriever scores are not calibrated probabilities. The motivation is to allocate reranking to queries where the retriever's first two choices have similar scores; this is a hypothesis about useful allocation, not proven epistemic uncertainty estimation.
Choose tau separately on each dataset's disjoint development set so approximately 30% of its queries route to the reranker. Freeze tau before test. The fraction routed on test can differ under distribution shift. Random and length routers have the same development routing target, same fixed models and candidate set, and share evaluation hardware. The length rule routes the longest queries. Gate computation has no model call; end-to-end measured latency includes it. Latency is per-query wall time on a single A100 at batch size one, with fixed software/hardware and warm-up. All models stay frozen. There is no router training or proof of guaranteed error control.
The CSV contains observed test accuracy in percent, mean end-to-end latency in ms, and test routing fraction. Results are from one frozen retriever/reranker pair and one run per condition. We have not measured confidence intervals, energy, or other hardware. No claim about true uncertainty or universal dominance follows. A potentially useful result is the tradeoff compared with always reranking; the margin heuristic's advantage over a simple length rule is mixed. Relevant prior selective computation and reranking work will be positioned later; do not claim a first-ever approach.
